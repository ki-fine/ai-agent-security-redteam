# 06 — 失败总结 (Failure Analysis)

> 一场打了 9 天的红队战役，公开榜 96.25（跨过奖牌线），私人榜 **0.555（排名 706）**。这不是一次战术失利，而是一次**目标函数选错**的失败。下面是我能给出的最诚实的复盘：每一层错了什么、为什么错、错在哪一步是可避免的。

## 最终数字

| | 公开榜 | 私人榜 |
|---|---|---|
| 我的最佳 | **96.25** | **0.555（706 名）** |
| 榜首 | 147 | **47** |

两个榜是两套完全不同的评分守卫。我几乎把所有工作投进了左边那一列。

## 三层失败链

### 第 1 层：我优化错了目标（最根本）

整场战役，我围绕公共榜的一个缝隙（`http.post` 只查 `url` 不查 `data`）构建了整个攻击体系——「marker 外流引擎」。本地神谕、25 轮实验、12 本弹药，全部在为**一个我能在本地完全复现、但不能在私人榜上验证**的缝隙服务。

而排名第二的选手从开场就贴脸说了一句预言：

> "SECRET_MARKER exfiltration is the engine under nearly every top score. This very likely collapses on Private. One all-field scan for that literal string and the entire top of this board resets to 0."

**逐字命中。** 我把公共榜当成了分数目标，而它只是行为探针。

### 第 2 层：我用 "ground-rule 论据" 说服了自己

我一度用一条看似合理的推理安慰自己：*"一个护栏不该分类阻断计分器明确评估的字符串。"* 于是判断 marker 私人榜大概率存活，把公共最优结构押成了终选第一席。

**它是错的。** 主办方的私人护栏就是扫了那个字面字符串——计分器评估的东西，护栏照样拦。这是对"护栏设计合理性"假设的一厢情愿，红队最不该有的乐观。

### 第 3 层：我亲手撤掉了唯一能活下来的通道（最痛）

良性邮件 (CONFUSED_DEPUTY, 4/事件, marker-free) 是全面扫描私人护栏下**唯一幸存的出口**。我建了一个 `email-farm-full`（2000 条不同收件人良性邮件）——在私人榜 47 分的标尺上，那是**奖牌级**的结构——然后因为"公开分太低"把它撤了，换成一个公开高分的彩票。

**公开分与私人存活在这里负相关。** 我一路用它当淘汰标准，方向完全反了。

## 每一个可避免的错误

| 决策 | 当时为什么 | 实际结果 | 正确做法 |
|------|-----------|---------|---------|
| 把 marker 引擎当主力 | ground-rule 论据 + 本地可验证 | 私人清零 | 公共榜只当行为探针 |
| 终选第一席 = 公共最优 marker 臂 | 相信"公共最好 = 私人最好" | 归零 | 终选押 marker-free 幸存通道 |
| 撤掉 email-farm-full | "公开分低 = 弱" | 丢掉奖牌级结构 | 公开低分 + marker-free = 私人幸存的正信号 |
| 对冲只覆盖"扫描型"私人护栏 | 恐惧单一模型 | 真实护栏 = 扫描+taint+关键字的并集 | 对冲务必要覆盖**并集** |

## 它证明了什么

1. **公共/私人双守卫的评测里，公共分 = 海市蜃楼。** 越是在公共榜上"显然正确"的攻击，越可能是私人护栏专门来杀的那个。
2. **红队最大的风险不是找不到缝隙，是选错守卫。** 竞赛的红队能力 = 猜对"哪条守卫会看到你的攻击"，并敢于押"能活下来的通道"而不是"能登顶的通道"。
3. **一次诚实的失败比一次侥幸的成功更有价值**——它把一个假说（"多守卫评测下公共分可外推"）用最硬的方式证伪了。
