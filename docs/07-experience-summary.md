# 07 — 经验总结 (Experience Summary)

> 这不是一篇"我赢了多少"的展示，而是一份**我在这 9 天里真正学会并验证过的东西**的清单。它对我自己和对下一个类似问题都有用。

## 技能与能力（可直接写进简历/技术面）

### 逆向工程 / 源码级理解
- 通读 `aicomp_sdk`（scoring / predicates / cells / guardrails / sandbox）与部署侧 `kaggle_evaluation` 网关，**逐行**重构出评分模型与守卫缝隙：谓词严重度、去重后仍累加的 severity、cell 签名（工具事件指纹：域名字段桶/收件人桶）、`_extract_target` 键序、taint 窗口、生成/回放预算。
- 通过**函数行为实验**（本地 oracle）与**分数反推**交叉验证源码读法——区分"源码允许"与"模型真会做"。

### 本地 oracle 构建
- 用 `.venv` 装出生产栈的**忠实复刻**：同 GGUF 权重（llama.cpp）、同 SDK agent、**同板级解析器**（`KaggleGemma4ToolCallParser`，而非 SDK 默认）、同 `OptimalGuardrail`、同 `seed=123` 与贪心解码。
- 识别出**本地默认解析器 ≠ 板级解析器**：用默认解析器测 = 悄悄测错了东西。这教训直接修正了 gemma 的结论。

### LLM / Agent 行为分析
- **引导性注入**（FRAME harmony）对多跳工具调用的"承重"作用，用一次干净 A/B 量化（83.25 vs 51.61）。
- **板级 gemma 恰好每消息一次工具调用**（>1 调用/回合 = 硬错误 → 整条消息归零）——13 种措辞 / 5 组 probe 验证，结构性不可 prompt。
- **确定性**（贪心 + 固定 seed）→ 逐字副本回放零方差 → 重复/复制策略的货币基础。

### 对抗性实验设计
- 每发一个变量、A/B 臂隔离、天气感知的跨日对比（服务器速度每日 ±2-3）。
- 用**对照臂**让标量可读：两臂 gemma 分支相同 → 公开分差 ≈ gpt 分支差/2，从而在没有行拆分时也能分离变量。
- 写**决策表**（情景 → 动作），出分后机械执行，不在出分后重新解读。

### 独立外部复核纪律（本战役最高价值单项）
- 每轮提交前请**独立 agent** 审计代码与算式；它抓出了所有真正致命的错误：非唯一分解被当事实的"4 发帽"、8 发算术错误、农场 vs 副本的支配关系、生成预算的漏算。
- 学会把"审计结论"与"主 agent 的判断"分开，以源码/算式为准。

## 认知升级

1. **确定性的两面性**：贪心+固定 seed 让复制策略可靠，但也意味着"一个本地观察"代表整个回放——一旦方向错，全部押注一起错。
2. **标量的不可辨识性**：当评测只回一个总分（无行拆分、无逐候选日志）时，任何"4/8 发、每候选耗时"的推断都是**非唯一分解**——只能在 A/B 中被验证，不能当事实引用。
3. **速度是乘数不是底数**：分数 ≈ (每候选击发数) × (预算内完成的候选数)。短消息只提高后者；前者（击发）必须先用结构（FRAME / 单调用）保住。
4. **红队 vs 评测设计的边界**：一个你测不到的守卫（本地无 wheel），意味着"公共可验证的高分"本质是**不可对冲的风险**。

## 可以带走的心态

- 输不是终点，**把失败写成可复用的知识**才是。这份 repo 里最值钱的不是"我发现了什么缝隙"，而是**"我以为我会赢，然后我错得有多具体，以及为什么"**。
- 下一次遇到任何"公共/私人分叉"的评测，第一反应应该是问：*"公共榜打不打得过私人榜的缝隙？如果打不过，公共分就是反向指标——那我该押哪个幸存通道？"*
